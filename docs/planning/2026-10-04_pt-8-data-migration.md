## 1. Findings

| id | Sev | Finding |

| **F1** | **C** | **Root-level refs cannot be saved under s3.** Every tracked sample carries `assets/inputs/<name>.png` (no campaign segment) [code: `briefs/sample-*.yaml`]; `parseStoredInputRef` answers `undefined` for it [code: `object-input-assets.ts:52-83`] and `resolveBriefAssetRefs` save mode throws `BriefRefNotFoundError` on it under s3 [code: `brief-asset-refs.ts`, "A ref that names NO campaign"]. | **F2** | **C** | **Report paths carry the slug, and the render key requires it.** `renderObjectKey` refuses a path whose first segment is not the campaign segment [code: `ObjectExporter.ts`], and `signed-urls.ts:247` derives every key that way from `outputPath`/`videoPath`/`htmlFallbackPath`/`proofPath`/`htmlBundlePath`. A slug that changed on import would need a report rewrite and lose the report revision PT-3c preserved on purpose [code: `0003_report.sql`]. → slugs are never renamed (D218). |
| **F3** | **H** | **`decision`, `report`, `pool` are keyed by slug text with no foreign key** [code: `0002`, `0003`, `0005`]. Nothing in the schema stops an import writing a report for a campaign that does not exist; the importer is what must prevent orphans (D221). |
| **F4** | **H** | **`ObjectAssetStore.writeAsset` is an exclusive create** (EEXIST on a second `(campaign_id, kind, name)`) [code: `object-asset-store.ts:135-205`], and `AssetEntry` carries no `sha256`. Idempotence therefore needs a read-and-hash on EEXIST — possible through today's port (`readAsset`), so **no port or adapter edit** is needed (keeps PT-9's files untouched). |
| **F5** | **H** | **Upload rules are narrower than what legacy disks may hold:** `ASSET_NAME_PATTERN` is a lower-case basename with `.png/.jpg/.jpeg/.mp3/.m4a`, `MAX_ASSET_BYTES` is 2 MiB, and the route checks magic bytes [code: `asset-files.ts:17-22`, `assets.post.ts:19-71`]. | **F6** | **H** | **Brief revisions are not portable** (fs hashes the operator's bytes, pg hashes `dumpBrief`) [intent: PT-3d row]; reports and decisions ARE (both hash the same bytes) [code: `0003_report.sql`, `pg-decision-store.ts:15-20`]. | **F10** | **M** | **No Postgres backup is configured on staging** (`postgres.yaml`: one instance, `local-path`, no `backup:` stanza) [code]. A rollback needs a dump taken by the runbook. |

## 2. Decisions proposed

| id | Decision | Why |
|---|---|---|
| **D216** | **The target org is the org the tree was written under; overridable only to an existing org.** The process root maps to `local`, `orgs/<id>/` to `<id>` — the inverse of `tenantRoot` [code: `run-environment.ts`]. `--org <id>` may override it but must name an existing `org` row, or the run refuses. Imported campaigns get `team_id = null` (org-wide, D166). | `auth:bootstrap` already makes the owner an owner-member of `local` [code: `bin/auth.ts`], so on staging `local` IS the owner's org. Deriving the org from the tree means a multi-org PVC needs no flag. |
| **D217** | **The CLI's source is a filesystem tree plus the target's own database; database-to-database copies are out of scope.** `--project-root` and `--output-root` default to `PROJECT_ROOT` / `OUTPUT_DIR` through `config.ts`, as the app resolves them. Class (X) (Aiven rows) is not handled; see Q1. | Keeps PT-8 one tool with one target. Copying rows across databases means id and actor mapping across two auth systems — a separate plan if the owner wants it. |
| **D218** | **Slugs are preserved, never renamed.** A slug that already exists in the target org (and is not this import's own earlier result, D221) is **refused** and listed. A reserved slug (`assertNotReserved`) or one that fails `SAFE_ID_PATTERN` is refused. Two source files declaring the same `id` refuse both. | F2: renaming would rewrite every report path and drop the report revision. |
| **D219** | **A ref that names no campaign, or names another campaign, becomes an asset OF THE REFERENCING campaign.** For each distinct ref in a brief (`products[].logoPath`, `products[].inputAsset`, `audio.path`, `copy.timeline.beats[].background`): an own-campaign path → that input's row; a root-level `assets/inputs/<name>` or any other safe path under `assets/` → the file is written as an asset of THIS campaign, named by its basename; `assets/inputs/<other-slug>/<name>` → that ONE file is written into this campaign. A name collision with different bytes takes the same suffix shape as `ObjectAssetStore.destination` (`<stem>-<from><ext>`, then `-2` …), retried through the PORT's `writeAsset` (the adapter's `destination` is private, and PT-8 edits no adapter); `<from>` is the source slug for an other-campaign ref and the literal `root` for a root-level or other-`assets/` ref. Identical bytes reuse the row (EEXIST → `readAsset` + sha256, D221). Every ref is rewritten to the row's id with `rewriteAssetPaths(brief, slug, slug, refToId)`. **Accepted (plan review):** because the importer acts as org owner (D220), this can copy a file across teams within the org — that is D210(b)'s existing copy rule applied to the importer, not a new leak; 8b's and 8e's PR bodies say so. | F1. D210(b): a foreign asset is copied, never shared. Copying only the referenced file (not `copyAssets`' whole set) is D211(b)'s logged follow-up applied from the start: an import should not inflate a campaign with assets it never used. |
| **D220** | **Imported versions are written through the existing ports as an import actor.** The importer acts as `TenantContext { orgId, userId: "import:pt-8", roles: ["owner"], teamIds: [] }`, so `PgBriefStore` stamps `brief_version.actor = 'import:pt-8'`. Campaign row via `createCampaign(slug, { name, type })` (from `campaign.json`, else null), then `createBrief` for version 1. Decision rows keep their recorded actors. | Provenance with no new column. The ports already enforce safe and reserved slugs and the version insert. |
| **D221** | **Idempotence by natural keys and content digests; no ledger table, no migration.** Campaign by `(org, slug)`; an existing campaign whose latest version body equals what this run would write — the **rewritten** body, refs already mapped through `refToId`, never the raw source bytes (PT-8-3) — is **unchanged**, any other existing campaign is **refused** (D218). Asset by `(campaign, name)`: on EEXIST, `readAsset` + sha256 compare (equal → reuse, else take the D219 suffix). Report/pool/decision: equal revision → skip, different → refused. Render object: `put` with `ifNoneMatch: "*"`; on 412, `get` + sha256 (equal → skip, else refused). **A second `apply` over the same source writes nothing.** Report, pool and decision rows are written only for campaigns this run created, completed or found unchanged; renders for any report row whose campaign exists (D223). | No `0017` migration, so no numbering race with PT-9. Accepted cost: a campaign a user created under the same slug cannot be told apart from "imported, then changed since"; both are refused and listed, which is the safe answer. |
| **D222** | **Legacy inputs pass the upload rules, and a campaign with a ref the import cannot satisfy is refused whole.** A file fails import if its name fails `ASSET_NAME_PATTERN`, it exceeds `MAX_ASSET_BYTES`, or its magic does not match its extension (the same checks as `assets.post.ts`). A brief whose ref points at a missing, unsafe or refused file is **refused with the ref named** — never imported with the path left in place. | Importing with a path left would render ENOENT under s3 and keep D214(c)'s dirty-after-Save defect alive; refusing is loud, and the operator fixes the file and re-runs (D221 makes that safe). |
| **D223** | **Renders: only what a report row names, and only for a report in this run's write set (PT-8-1).** "In scope" is exactly: (a) campaigns 8b's apply imported (created, completed, or found unchanged); (b) campaigns 8e normalised; (c) class-P campaigns with no upload at all — no path ref, no asset row, `campaign.created_at` before `--switched-at <iso>` (8a's flag, PT-8-1). For each report in scope, each of the five path fields that is a non-empty string is read from `<output-root>/<path>` and written to `renderObjectKey(renderPrefix(org, campaignUuid), slug, path)` with `contentTypeFor`'s type. A missing file or an extension `contentTypeFor` refuses is listed per path; the report is still imported (the grid shows its honest placeholder, D213). Files under `<output>/<slug>/` that no row names are **counted, not imported**. A report row OUTSIDE this scope that still has a source file and a missing object is **listed as out of scope, never written** — it may be a live campaign already on `s3` that a user is editing today, and this importer must not touch its renders. | The report is the only reader of a render (`signed-urls.ts`); orphans are superseded variants. Scoping the WRITE set, not just the read, is what keeps the importer off a campaign no probe verified as safe. |
| **D224** | **Packages are not imported; they are regenerated.** The export page lists no packages for an imported campaign until someone packages it again, which is derived from the renders this import wrote. The census counts each `<output>/<slug>/packages/**` and top-level `<output>/packages/**` platform directory it skips. | F9: a translation would rewrite manifests into generation prefixes for data that is derived anyway. |
| **D225** | **`plan` is the default and is read-only (not fs-only); `apply` needs `--expect <digest>` and a quiet target.** `plan` writes a JSON report and prints a summary and touches no row or object. When a database is configured it also PROBES the target read-only (the org row exists; per slug absent / unchanged / refused; class-P campaigns that would be normalised); without one it is fs-only and says so in its header. It prints a digest that is **source-only** (sha256 of the canonical source plan, including every source file's sha256), so the digest names what the owner reviewed and apply's own D221 probes refuse on a target that moved since. `apply` re-plans, refuses unless the digest equals `--expect`, refuses unless `STORE_BACKEND=postgres` and `OBJECT_STORE=s3`, and on staging runs with the app Deployment scaled to 0. | What the owner reviewed is what runs; a source that changed in between refuses. Scaling to 0 stops a user creating a colliding slug mid-run (F12). |
| **D226** | **One ref walk, moved to a leaf file.** PT-8a moves `collectRefs` out of `brief-asset-refs.ts` (where it was private, F11) into `asset-files.ts` — already a leaf (no imports of its own beyond `node:path` and the brief type), which is what makes a straight export safe where it would otherwise risk a module cycle with `pg-brief-store.ts` (PT-9-6) — and `brief-asset-refs.ts` re-exports it for its own existing callers. The importer, the normaliser, `verify`, and PT-9's 9d (D236's uuid-ref check) all import it from `asset-files.ts`. | F11: two copies of "which fields are refs" can disagree. This is now a real file PT-8a owns that PT-9's 9d depends on — not a one-word shared edit but a cross-plan dependency (PT-9-6): 9d cannot start until PT-8a has merged. |
| **D227** | **Not imported, and listed with counts in every plan:** jobs (`<output>/jobs/`, transient); the background cache (regenerates; per-org prompts); drafts (`briefs/<slug>/drafts/<userId>.json`: the user is the fs `local` identity, and `base_revision` would be stale because brief revisions change, F6); last-opened (`state/last-opened/`); usage; provider keys (pg only); templates (canonical, in memory); packages (D224); the retired `<output>/report.json` pointer (PT-0a); renders no report names (D223); non-brief files in `briefs/` (`.md` and the rest: name and count only); briefs the parser refuses (F8), each with the parser's message. | "Never silent" (PT-8 row). Every skipped item appears in the plan as a counted category. |
| **D228** | **Class (P) is normalised in place.** For each campaign in the target org whose latest version still carries a path ref: its `assets/inputs/<slug>/` files become `asset` rows and objects (D219/D222 rules), its refs are rewritten to ids, and the result is written as a NEW version through `rewriteBrief(…, { expectedRevision })` as `import:pt-8`; a 409 is listed and skipped. Its report's renders follow D223. Rows it already has (report, pool, decision) are left alone. | D210(e) and D214(c). A new version, not an edit in place: `brief_version` is the audit trail (D169). |
| **D229** | **Rollback is a restore, not code.** The staging runbook takes a `pg_dump` of `app` before `apply` (F10) and keeps the plan JSON. `apply` also writes a result JSON listing every campaign uuid, asset id and object key it minted (8b, 8d). Rolling back = restore the dump, then `delete` exactly the keys in that file (after the restore no row references them, and no read can reach them meanwhile). A scripted per-campaign rollback uses PT-9's purge when it exists — PT-8 writes no delete code. | Keeps PT-8 out of PT-9's delete methods; on staging, a restore inside the maintenance window loses nothing. |

## 5. What this plan refuses

- Renaming a slug to dodge a collision (D218).
- Leaving a path ref in an imported or normalised brief (D222, D228).

## 6. Definition of done

1. `yarn import plan` over the staging tree lists every campaign as importable / unchanged / refused-with-reason, and the D227 census, with no row or object written (a test asserts zero writes).
2. `apply --expect <digest>` followed by a second `apply` writes nothing the second time (rows and `put`s counted).
3. `verify` exits 0 on staging: counts match, every input and render hash matches its source, report and decision revisions match, **zero path refs** in the org's latest versions.
4. A class-P campaign re-saves under s3 without a 404 and does not read as unsaved after Save (D214 c closed): checked by hand on staging after the run.
5. The PR bodies say that brief revisions are not kept (PT-3d) and that packages need re-packaging (D224).

## 8. Risks

- **The real volume is unknown on staging** (Q0). `plan`'s read-only probe and 8e's own pre-dispatch measurement (PT-8-6) both exist precisely to size it before anything writes.
- **High-risk lanes are 8b and 8e** (they mint ids and write versions). Both are guarded by `--expect`, by D221's refuse-on-difference, and by 8f's hash and zero-path-ref check.
- **A legacy brief may fail today's parser** for reasons other than `html` (schema drift). Each is refused with the parser's message; the fix is in the source file, then a re-run.
- **Upload rules may refuse real operator files** (upper-case names, files over 2 MiB). D222 refuses the campaign rather than guessing a rename; if the plan shows many, a follow-up can add an explicit, listed rename rule.
- **A user-created campaign under an imported slug** reads as a conflict, not as "already imported" (D221's accepted cost).
- **Rollback depends on the runbook's `pg_dump`** (F10): if it is skipped, there is no restore. 8g's README makes it step 2, before scale-down.
